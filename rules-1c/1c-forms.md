# Формы 1С: разметка по аналогу

Применяется при создании новой управляемой формы объекта (документ, справочник, отчет, обработка) и при
заметной переделке разметки существующей формы, если правила проекта не требуют иного.

- **Сначала найти аналог в той же конфигурации.** Один или два ближайших типовых объекта того же вида и
  назначения: для кадрового документа с сотрудником и периодом - типовые кадровые документы, для ведомости -
  типовые ведомости, для отчета с параметрами - типовой отчет той же подсистемы. Общие архетипы из скилла
  `1c-form-patterns` использовать, только если аналога нет.
- **Посмотреть разметку аналога**, а не только его реквизиты: через EDT MCP `get_form_layout_snapshot` и
  `get_form_screenshot`, при недоступности MCP - по `Form.form`. Записать для себя структуру: группы шапки и их
  колонки, строка номера и даты, место организации и подразделения, страницы и таблицы, подвал (комментарий,
  ответственный), командная панель, встроенные элементы БСП (печать, присоединенные файлы, дополнительные
  реквизиты, связанные документы).
- **Повторить структуру и порядок групп аналога** в новой форме, с теми же видами групп, выравниванием и
  растягиванием полей. Свои элементы добавлять в ту группу, где аналогичные данные стоят у аналога.
- **Проверить результат скриншотом.** Перед сдачей снять `get_form_screenshot` новой формы и сравнить со
  скриншотом аналога при стандартной ширине окна: нет ли полей во всю ширину без нужды, пустых групп,
  разъехавшихся колонок, комментария посреди формы. Если доступен запуск клиента, проверить и в нем.
- **Отступления объяснять.** Если разметка сознательно отличается от аналога, коротко указать причину в отчете
  о задаче. В отчете назвать использованный аналог и приложить путь к скриншоту.
- **Собственные формы размечать в редакторе формы (XML), а не кодом.** Группы, страницы, таблицы и поля своей
  формы описываются в `Form.form`; создавать их в `OnCreateAtServer` через `Items.Add`, `ChangeAttributes` и
  перемещать через `Items.Move` без явной необходимости нельзя. Скрытие по правам делать не созданием элементов,
  а штатно: элементы данных без права View платформа скрывает сама, остальное через `Visible` и
  функциональные опции. Программное добавление допустимо для заимствованных типовых форм (их XML не меняем)
  и для действительно динамического состава (колонки по данным, заранее неизвестные), с причиной в комментарии.
- Правила проекта о заимствованных формах (изменение только программно, без правки XML) имеют приоритет:
  для заимствованной формы аналог задает, куда ставить добавляемые элементы, а не повод менять ее разметку.
