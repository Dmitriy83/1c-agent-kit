# Проверенные ограничения EDT MCP 2.6.1

Проверено 17.11.2026: плагин `com.ditrix.edt.mcp.server` 2.6.1, EDT 2026.1.2.2.
Эти сведения относятся к этой сборке, а не ко всем MCP-плагинам для EDT.

- `delete_metadata(confirm=true)` может ожидать модальное подтверждение
  `DestructiveConsentGate`. Таймаут клиента не отменяет серверную операцию.
  Не создавать новый объект с тем же FQN и не подменять удаление правкой файлов,
  пока журнал EDT или повторное чтение модели не подтвердит завершение/отмену.
  Подтверждение в EDT может действовать до конца текущей сессии.
- `create_metadata` для собственной роли создает `.mdo`, но в проверенной сборке
  не инициализирует редактируемую модель `Rights.rights`. Последующий
  `modify_metadata(rights=...)` отвечает `this role has no editable rights model`.
- `get_metadata_details(assignable=true)` объявляет `uuid` строковым свойством,
  однако `modify_metadata` передает строку в setter, ожидающий `java.util.UUID`.
  Не считать ответ assignable доказательством работоспособности записи UUID.
- `objectBelonging=Native` само по себе не очищает `extendedConfigurationObject`
  и блок контроля заимствования. Пустая строка и `null` для этой ссылки отвергаются.
  Проверять фактическую модель и `.mdo`, прежде чем удалять базовый объект.
- `modify_metadata` не разрешает вложенную форму как цель `defaultObjectForm`
  (`Reference target ... was not found`), хотя форма существует в модели.
  `create_metadata(setAsDefault=true)` на заимствованном владельце может задать
  свойство в BM, но не экспортировать его без флага `defaultObjectForm=Extended`.
- `modify_metadata` не разрешает корень `Configuration.<Name>`; в этой сборке
  нет отдельной операции записи версии конфигурации.
- `write_module_source` при создании нового BSL-файла сохраняет UTF-8 BOM и LF,
  даже если исходная строка имела CRLF. При сравнении переноса отдельно проверять
  текст без BOM/нормализованные переносы и требования `.gitattributes`.

Для недоступной конкретной операции действует ограниченный fallback из
`rules-1c/mcp-tool-priority.md`: точечный перенос по проверенному эталону,
затем `revalidate_objects` (он обновляет проект с диска) и чтение ошибок.
Это не разрешение заменять недоступную EDT ручной записью и не способ обходить
диалог подтверждения или отказ автоматической проверки. Если проверка требует
явного согласия на файловую правку, получить его для конкретных файлов.

При переносе объекта из основной конфигурации в расширение сохранение UUID
не гарантирует сохранение связей БСП: идентификатор меняет тип с
`CatalogRef.MetadataObjectIDs` на `CatalogRef.ExtensionObjectIDs`.
Отдельно проверять профили ролей, пользовательские варианты и настройки отчетов.
