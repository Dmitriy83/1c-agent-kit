# /vanessa-run - прогон сценариев Vanessa Automation

Запускает `.feature` (файл или каталог) в Vanessa Automation в пакетном режиме и возвращает результат.

Как это работает: скрипт пишет `VAParams.json`, запускает тонкий клиент в режиме менеджера тестирования
(`1cv8c ENTERPRISE /TestManager /Execute vanessa-automation.epf /C"StartFeaturePlayer;QuietInstallVanessaExt;VAParams=..."`),
Vanessa сама поднимает клиент тестирования по своим настройкам (по умолчанию «Этот клиент» - та же база
и тот же пользователь), выполняет сценарии, пишет JUnit и файл статуса и завершает работу. Скрипт ждет
окончания (с таймаутом), разбирает JUnit и печатает итог.

## Перед запуском

1. **Проверь шаги** сценария скилом `1c-vanessa-steps` (validate.py): несуществующий шаг падает только на прогоне.
2. **В фиче есть подключение клиента тестирования.** Vanessa в пакетном режиме сама его не подключает:
   без шага подключения все UI-шаги падают с «Клиент тестирования не подключен». Добавь в начало фичи
   ```gherkin
   Контекст:
   	Дано Я открыл новый сеанс TestClient или подключил уже существующий
   ```
   При ручном запуске с уже подключенным клиентом шаг его переиспользует. Профиль клиента берется из
   настроек Vanessa этого пользователя (по умолчанию «Этот клиент» - та же база). Пароль из `-Password`
   уходит только менеджеру: если у пользователя клиента есть пароль, задай его в профиле клиента
   в настройках Vanessa заранее, иначе клиент не войдет и UI-шаги упадут.
3. **База обновлена** под текущий код (EDT `update_database` или Конфигуратор). Скрипт базу не обновляет.
4. **Vanessa не открыта вручную в этой базе** под тем же пользователем: второй менеджер тестирования
   мешает клиенту тестирования и держит базу (реструктуризация потом не пройдет).

## Параметры подключения

Как в `1c-db-run`: прочитай `.v8-project.json` из корня проекта, возьми `v8path` и разреши базу
(параметры пользователя -> имя/alias -> ветка Git -> `default`). Путь к Vanessa: параметр `-VanessaPath`,
иначе переменная окружения `VANESSA_EPF`, иначе поле `vanessaPath` в `.v8-project.json` (если есть).
Если ничего не задано - найди `vanessa-automation*.epf` поиском и спроси пользователя, какой взять.

## Команда

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File skills/1c-vanessa-run/scripts/vanessa-run.ps1 <параметры>
```

| Параметр | Обязательный | Описание |
|----------|:------------:|----------|
| `-Feature <путь>` | да | `.feature` файл или каталог фич |
| `-VanessaPath <путь>` | нет | `vanessa-automation.epf` / `vanessa-automation-single.epf`; по умолчанию `VANESSA_EPF` |
| `-V8Path <путь>` | нет | Каталог bin платформы или `1cv8c.exe`; по умолчанию последняя полная установка (с `vrsbase.dll`: неполная падает при старте с «Ошибка загрузки компоненты vrsbase»). Лучше задать платформу, совпадающую с версией базы |
| `-InfoBasePath <путь>` | * | Файловая база; по умолчанию `VANESSA_IB_PATH` |
| `-InfoBaseServer <сервер>` | * | Сервер 1С; по умолчанию `VANESSA_IB_SERVER` |
| `-InfoBaseRef <имя>` | * | Имя базы на сервере; по умолчанию `VANESSA_IB_REF` |
| `-UserName <имя>` | нет | Пользователь 1С; по умолчанию `VANESSA_IB_USER` |
| `-Password <пароль>` | нет | Пароль; по умолчанию переменная `VANESSA_IB_PWD` (не передавай пароль в открытом виде, если есть переменная) |
| `-Tags <список>` | нет | Отбор сценариев по тегам через запятую |
| `-IgnoreTags <список>` | нет | Теги исключения через запятую |
| `-StopOnError` | нет | Остановиться на первой ошибке |
| `-TimeoutMinutes <N>` | нет | Таймаут прогона, по умолчанию 30 |
| `-OutDir <каталог>` | нет | Каталог результатов, по умолчанию временный |
| `-ParamsFile <путь>` | нет | JSON с дополнительными ключами VAParams (запись видео, озвучка); сливается с параметрами скрипта |
| `-KeepProcesses` | нет | Не закрывать менеджер и клиентов принудительно (в том числе по таймауту); для записи видео |

> `*` - нужен либо `-InfoBasePath`, либо пара `-InfoBaseServer` + `-InfoBaseRef`

Прогон UI-сценариев идет минутами: запускай команду в фоне (`run_in_background`) с таймаутом инструмента
больше `-TimeoutMinutes`, и дождись уведомления о завершении.

## Результат

Скрипт печатает Markdown: таблица итогов (всего, прошло, упало, пропущено, время, статус Vanessa),
список сценариев с отметкой `[+]`/`[x]`/`[-]` и текстом ошибки упавших, пути к скриншотам ошибок
и каталог результатов (там `VAParams.json`, `junit/`, `screenshots/`, `status.log`).

Код возврата: `0` - все прошли, `1` - есть упавшие (или Vanessa вернула ошибку вне сценариев), `2` -
прогон не состоялся (нет отчета, таймаут, ошибка параметров). В начале отчета печатаются выбранная
база и платформа: явные `-InfoBasePath` / `-InfoBaseServer`+`-InfoBaseRef` важнее переменных окружения,
из переменных `VANESSA_IB_PATH` важнее пары сервер/база. После прогона скрипт закрывает клиенты тестирования, запущенные этим прогоном
(`ЗавершитьРаботуСистемы` закрывает только менеджер, а оставшийся клиент держит базу, и обновление
конфигурации потом не проходит); по таймауту закрывает и менеджер. Если отчета нет, скрипт печатает
сообщения платформы из лога `/Out` (`1c-out.log`), например ошибку запуска клиента.

## Разбор упавшего сценария

1. Прочитай текст ошибки и скриншот (Read по пути из вывода).
2. Если ошибка в шаге (элемент не найден, окно не открылось) - сверь имена элементов формы с метаданными
   (`.form`) или открой форму в базе. Если ошибка в данных - проверь подготовку данных в сценарии.
3. Исправь фичу или код, обнови базу при изменении кода и прогони снова.

## Подводные камни

- **Код на сервере в шаге «я выполняю код встроенного языка на сервере»** выполняется в контексте формы
  Vanessa: имена переменных `Элементы`, `Объект` и другие свойства формы заняты, присваивание им падает
  с «Поле объекта недоступно для записи». Называй переменные иначе (`ТестовыеДанные`).
- Этот шаг выполняет код в базе **менеджера тестирования**. Скрипт запускает менеджер в той же базе,
  что и клиент, поэтому данные готовятся там же, где проверяются.
- **«Выбор по строке» при отсутствии данных** подставляет похожее реальное значение (например, другую бригаду),
  и сценарий может что-то записать на чужих данных. Готовь тестовые данные в первом сценарии и давай им
  узнаваемый префикс.
- **Повторный запуск** должен быть возможен: подготовка данных сначала помечает на удаление данные
  прошлого прогона (пометка удаления снимает документ с проведения).
- **Дата нового документа в форме** - начало сегодняшнего дня, время платформа подставляет при записи.
  Логика, которая зависит от даты документа до записи (состав на дату, проверки заполнения), в UI-сценарии
  видит 00:00 - такие ошибки юнит-тесты с явной датой не ловят, а сценарий Vanessa ловит.
- Окна менеджера и клиента тестирования открываются на рабочем столе: прогон требует интерактивной
  сессии Windows.
- **Сканер штрихкода не эмулируется в пакетном прогоне.** Шаг «я эмулирую сканирование штрихкода БПО
  "..." через буфер обмена» падает с «Значение не является значением объектного типа (НачатьВызовЗаписатьТекст)»:
  объект компоненты VanessaExt не создан, а даже с ним нужен настроенный в базе сканер БПО. Формы, которые
  принимают коды только через внешнее событие оборудования, проверяй без скана: данные готовь серверным шагом
  той же операцией, что вызывает форма, а в UI проверяй остальное (выбор, подсказки, связанные формы).
- **Кнопки системного вопроса** (`ПоказатьВопрос` с ДаНет) - на языке клиента: в русской базе `'Да'`/`'Нет'`,
  а не `'Yes'`. Ошибка «Кнопка/команда с заголовком <Yes> не найдена», активная форма `MessageBox`.
- **Кнопки, созданные программно** (например, кнопки выбора линии `Кнопка_ВыбратьЛинию_0`), нажимай по
  заголовку (`я нажимаю на кнопку "Линия - Продукт"`), а не по номеру: порядок зависит от данных базы.
- **Упавший сценарий может съесть весь таймаут.** После ошибки Vanessa снимает скриншот внешней программой
  (в настройках - IrfanView); если она не отрабатывает, прогон висит до `-TimeoutMinutes` и отчета нет
  (код 2, «нет файла»). Видишь код 2 у фичи, где в журнале есть упавший шаг, - сначала чини шаг.
- **Данные, созданные в одну секунду,** неупорядочены по времени: «последний короб» по дате сканирования может
  оказаться любым из созданных серверным шагом. Проверяй то, что не зависит от порядка.
- **После поднятия версии конфигурации** клиент тестирования не подключается: «Вход в приложение временно
  невозможен в связи с обновлением на новую версию». Обновление ИБ БСП не выполняет ни EDT `update_database`,
  ни прогон YAxUnit. Запусти его один раз на тестовой базе:
  `1cv8c ENTERPRISE /F "<база>" /N <админ> /C "ЗапуститьОбновлениеИнформационнойБазы;ЗавершитьРаботуСистемы" /DisableStartupDialogs`.

## Запись видеоинструкции

Видео пишет сама Vanessa в пакетном прогоне: ключи записи передай файлом `-ParamsFile` (JSON сливается
с `VAParams.json`), запускай с `-KeepProcesses -StopOnError`. Готовое видео - `<videopath>/Video/<фича>.mp4`.
Пример параметров записи с озвучкой Yandex SpeechKit и плавным курсором -
[references/video-params.example.json](references/video-params.example.json): скопируй в игнорируемый Git
файл проекта, пропиши пути своей машины и ключ. Видеоверсии фич держи в отдельном каталоге
**вне** каталога проверочных фич (`features-video/`, а не `features/video/`): Vanessa ищет фичи рекурсивно,
и обычный прогон `-Feature features` подхватил бы видеосценарии с кликами по координатам и своими настройками.
Пути к файлам в шагах задавай через `$КаталогФичи$` (каталог текущей фичи; `$КаталогПроекта$` в пакетном
прогоне может быть пуст, если не задан `projectpath` или `workspaceRoot`; Vanessa подставляет переменные в параметры
шагов), а не абсолютными путями машины.

Окружение:

- ffmpeg **64-битный** (`winget install Gyan.FFmpeg.Essentials`): 32-битный на большом экране падает
  `malloc ... failed` при замедлении фрагмента.
- ImageMagick 7: `"convertcomand": "magick"`, каталог установки в PATH процесса скрипта (оболочка, открытая
  до установки, его не видит).
- `"hideservicewindows": true` обязателен: без него перегонка wav в mp3 идет через `КомандаСистемы` -> `cmd /c`,
  который срезает кавычки, и ffmpeg молча не запускается.
- Область захвата `screenleft/screentop/screenwidth/screenheight` (gdigrab) - без панели задач
  (`[System.Windows.Forms.Screen]::PrimaryScreen.WorkingArea`), размеры четные.

Озвучка (`ttstype` - **число**, строка не распознается):

- `0` - Microsoft TTS через консольный balcon (`audioenginetts`, `ttsvoice` - часть имени голоса). Голоса
  Windows (Irina) звучат плохо и путают ударения: годится только для отладки записи.
- `1` - Yandex SpeechKit (`yandexttsapikey`, `yandexttsvoice` например `alena`, `yandexttsspeed`,
  `yandexttsemotion`). Ударение - `+` перед ударной гласной (`расформиров+ать`) через словарь замен
  `changewordslib` (путь к txt). Облачные движки (Yandex `1`, Amazon `2`, Сбер `3`, 1С `4`) отправляют текст
  во внешний сервис - согласуй с пользователем. Ключи - только в локальном игнорируемом JSON, не в чат и
  не в Git; скрипт стирает их из рабочего `VAParams.json`, как только запущен клиент тестирования (запасной
  срок - половина таймаута, не меньше 5 минут), и еще раз после прогона.
- Субтитры (`addsubtitles`) обычно лучше выключить: `#[autodoc.mute]` гасит только голос, а подпись шага
  («И Пауза 2») остается.

Разметка: директивы `#[...]` строками прямо над шагом. `#[autodoc.text] Текст` - озвучить шаг своим текстом
(пояснение звучит во время действия), `#[autodoc.mute]` - показать без озвучки, `#[autodoc.ignorestep]` -
выполнить без показа, `#[autodoc.ignore.scenarioslide]` над сценарием - без титульного слайда. Шаг без
директивы озвучивается своим техническим текстом. Подготовку данных выноси в отдельный скрытый сценарий.

Курсор и блокирующие формы:

- Плавное движение мыши - только с `ЭмулироватьДвиженияМышкиVanessaExt = Истина`
  (`emulatemousemovementswithVanessaExt`); иначе курсор прыгает мгновенно.
- Форма, открытая с блокировкой всего интерфейса (рабочие места ТСД), ломает UIAutomation и передачу команд
  через основное окно и буфер обмена. На время таких сценариев выключи UIAutomation и автоматический подвод
  к элементам, подводи курсор явным шагом к координатам, команды передавай через мониторинг файлов событий
  (включить мониторинг до открытия формы). Внешние события оборудования (скан) - через
  `Оповестить("ScanData", ...)` в клиентском коде, переданном файлом события.
- **Успешный сценарий не гарантирует правильную картинку.** Во время записи именованное нажатие может
  сработать дважды (кнопка «Добавить» добавила две строки), меню может не перерисоваться без физического
  клика. После записи смотри кадры (`ffmpeg -vf "fps=1/6,scale=960:-1,tile=3x3"`), а ударения - на слух.

Диагностика: подставь вместо пути ffmpeg/balcon cmd-обертку, которая пишет `%*` и `%ERRORLEVEL%` в лог и
вызывает настоящий exe. Источник истины - модуль видео в распакованной epf VA (поиск по тексту ошибки).
Окно ошибки оставляет висеть менеджер (поэтому `-KeepProcesses`): попроси пользователя закрыть его до
следующей записи, иначе он попадет в кадр.
